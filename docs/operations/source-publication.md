# Source publication qualification

This optional, local-only path separates publication of an exact source commit
from a named historical cache incident. It does not qualify deployment, provider
operations, mail, migration, or cleanup. The historical receipt stays unchanged
and its unknown outcome and retained payload remain protected. The pre-push hook
has no fallback CI or retry: missing, stale, incomplete, untrusted, or changed
qualification records hold the push.

A source qualification is not an archive. Before a new CI run, independently
qualify current writer/output custody, protect all retained incident payloads
and other owners' work, and obtain normal Disk Guard admission for the exact
command and complete write paths. Preserve the original incident receipts. A
current-state archive must not be described as the old failure-time image. The
single compiler-root contract remains in force.

After those prerequisites and a clean committed candidate, the owner may run
`build-and-retire.py` with its existing exact resource request, a fresh proof
directory, an actual authorization reference, `--retain-cache`, and the exact
command `bash scripts/ci.sh`. The retain option only prevents the finalizer from
retiring cache; it does not protect files from build-time replacement. The
qualified run requires normal launch acknowledgement, both stream EOFs, a zero
exit, no unknown process generations, and observed natural reservation release.
An unproved settlement remains held and cannot issue a qualifying lifecycle
record. No enclosing-lifetime marker substitutes for genuine admission.

The CI child records inputs after frozen Bun installation and before the checks,
then captures them again with products after all checks. Both captures must match
for source, complete environment projection, CI script, dependency-resolution
and selected toolchain bindings. Products cover the five Worker bundle trees,
router WASM, UI Worker and UI site. The retained lifecycle record binds the
operation, settlement and run capture. This is evidence for review, not an
independent approval. `source_qualification.py` requires clean exact HEAD/tree,
locked offline Cargo metadata and external package source trees, the installed
node_modules tree, selected tools, Rust sysroot, SDK, wasm-pack cache and product
trees. Unavailable required files, escaping symlinks, ambiguous tool selections, changing
inventories, or unavailable metadata hold. Confined dangling links are recorded
with their unresolved state; an escaping or changed link remains a hold. A stable writer exclusion must be
established separately; a hash scan by itself cannot establish it.

The environment projection retains every variable value in a digest except the
lifecycle's own validated CI/admission markers and the canonical Cargo target
that CI unconditionally selects. The pre- and post-check CI captures must match that projection exactly. The
push environment has a separate, independently approved digest of the
source-reviewed publication projection; it is not equated to the CI environment. An unreviewed
change to either binding holds. The historical environment digests do not
establish equivalence for a new run. The
selected tool and dependency inventory is an explicit review target, not a
claim that OS version text alone authenticates every system dependency.

Before publication, an independent reviewer must review the exact successor,
run-bound evidence and guard source, and supply a separately expected review
digest. An operator-owned, mode-0600 `var/source-publication/selection.json`
selects one proof directory, the preserved incident receipt, one target ref,
expected remote SHA, remote name and remote URL digest. Separate owner-only
`approval.json` and `review.json` bind the exact capture, lifecycle, source,
incident and review. Three separately installed local Git configuration pins
(`maildesk.sourcePublicationSelectionSha256`,
`maildesk.sourcePublicationApprovalSha256`, and
`maildesk.sourcePublicationReviewSha256`) must match the canonical JSON digests.
The review pin must come from the independent reviewer, not from a self-authored
reviewer-name field. The source owner does not manufacture the review or its
expected digest. Exact schemas and required fields are defined in
`source_qualification.py` and verified by its fixture tests.

The guard rereads the original incident and requires its exact pinned digest and
`CACHE_RETAINED_SETTLEMENT_UNPROVED` status. It verifies the digest-bound capture,
input, lifecycle, operation, exit and settlement records, separately pinned review
and operator approval, current Git HEAD and tree, the separately approved full
push environment, and one non-deletion fast-forward ref update to the pinned
target and remote. The approval schema includes `publication_environment`: the
SHA-256 of the canonical publication environment projection at the hook. Lifecycle
markers are rejected there, not accepted as custody. The source owner and reviewer
must review the guard and the precise operative environment binding; transient
context variables can cause a safe hold. The projection retains dispatcher
configuration, worker selection, job data, and recursion markers; they are not
proof of dispatch. It excludes only shell nesting, previous-directory and
color preference, and Python bytecode suppression; the verifier uses `-B`
and invokes Git directly. The repository hook requires the installed global
chain's `--verify-chain pre-push` check, including effective hooks path and
registered hook digest, before evaluating the qualification. A direct
`.githooks` configuration or missing registration holds. This does not change
that configuration or register a pin.

Git-source publication consumes Git objects, not the live build outputs or
installed dependencies. The guard therefore does not re-read mutable products,
node_modules or toolchains at push time. Their run-bound digests support review
of that qualification only: they do not prove that live files still match, that
those products were published, deployed, installed, or accepted, or that every
system dependency is covered. Capture during CI still needs qualified custody
for the full observation and protection of retained outputs before that run.
The independent reviewer must assess those limits and accept the exact evidence.
The guard does not edit the records, change the old exit status, assume unknown
processes ended, or send mail. Normal global Git guards and repository hook
content pinning remain required; a modified hook needs independent review and
supported pin registration before it can execute.

For a no-network preparation check, invoke
`python3 -B scripts/source_qualification.py --print-publication-environment`
from the intended push context; it prints only the projection schema and digest,
not environment values. This command does not invoke a hook, authorize, or
attempt a push. The digest is usable only if the eventual hook sees the same
reviewed projection; an independently controlled approval must pin it. An
ordinary shell or separate automation invocation can have different bound
variables, in which case the later hook safely holds. Dynamic dispatcher job
data remains bound, including the per-dispatch temporary result path. The
standalone digest therefore cannot establish the future hook digest; a practical
independently pinned preflight remains unqualified. Publication stays held.

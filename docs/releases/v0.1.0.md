# maildesk-cf v0.1.0

Initial public template release for identity-preserving Cloudflare inbox relay.
Operators keep their existing inbox; Rust owns route and reply policy, Workers
perform delivery, and the dashboard reports routing health and distinct proof
states. This is a GitHub source/template release, not an npm package release.

## Included behavior

- Domain enrollment describes the complete intended domain universe and its
  mail ownership. Fleet-readiness compilation produces body-free, scope-bound
  reductions so selected canary results cannot stand in for fleet completion.
  The output explicitly identifies caller-supplied plane states: it does not
  authenticate the underlying artifacts or authorize a live-readiness claim.
- The isolated D1 preview config is materialized privately without exposing
  identifiers in command arguments or overwriting an operator-owned config.
  Policy imports use D1-compatible transaction behavior.
- Worker deployment proof binds the complete build closure, actual Wrangler
  entrypoint, active deployment/version metadata and bytewise artifact order.
  Matching provider annotations are metadata-only and cannot establish deployed
  artifact equivalence; actual byte/receipt qualification remains required.
  Mail receipts bind to the Git candidate; source, deployed artifact, provider
  acceptance and recipient receipt remain distinct claims.
- Template initialization preserves stable schema filenames and cfctl operation
  IDs while renaming instance resources. Its regression test uses real template
  contents rather than replacement-only fixtures.
- Production preflight checks the exact installed read-capability contract
  consumed by Maildesk. Missing/blocked/incompatible capabilities fail closed;
  catalog compatibility does not confer mutation or account authority.
- Dark planning names the exact owned Access application/policy contracts and
  can check their installed schemas. New applications start with no policy;
  a separately reviewed operator-group policy follows verified app identity.
- UI asset names hash the final JavaScript after rewriting its WASM reference;
  the build verifier compares every manifest digest with the emitted bytes.
- Credential instructions use the public cfctl lifecycle. The external raw-curl
  rotation wrapper and workstation-specific workaround have been removed.
- New instances follow inbox relay; existing web-desk integrations keep their
  explicit compatibility mode. Setup, positioning and roadmap now agree.
- The recovery runbook maps pending, ambiguous, partially accepted and terminal
  results to safe actions and retention deadlines. Missing unsent payloads
  remain identified as pending instead of being mislabeled as attempted sends.

- Production operations use one explicit account-bound cfctl profile and shared
  executable selection. Preflight no longer requires a duplicate Cloudflare API
  token, and another global profile cannot mask an unavailable selected one.
- Live collection uses the registered compiler-owned D1 projection and R2
  digest-only read. Raw remote Wrangler and mail-detail extraction are removed;
  mailbox receipt remains a separate proof requirement.

## Acceptance and limits

The release candidate must pass `bun run ci` and independent review against
`docs/acceptance-criteria.md` before its tag is published. Generated builds and
real provider/mail receipts are not included in the source template.

Production still requires account-bound cfctl capabilities, real resource IDs,
Access configuration, sender-domain verification and separately reviewed
activation. The template starts dark with outbound sending disabled. Publication
is not deployment or mail-readiness proof. No production endpoint is implied
by placeholder Wrangler configuration.

R2 retains bounded recovery content, with a seven-day default lifecycle.
Ambiguous Cloudflare sends are never automatically replayed; unavailable exact
provider evidence or expired content may leave an incident explicitly unresolved.
Operator-authored outbound attachments are unsupported. No customer outcome,
reliability SLO or market-demand claim is made.
